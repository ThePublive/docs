Publive DXP is a headless CMS for digital publishers and enterprises. Your team writes, reviews, and publishes content in the Publive DXP dashboard. Your website or app gets that content through APIs, so you can build the frontend with any framework.

## Use cases

### Publish news and digital media

Publive DXP supports the main content formats of digital publishing:

| Post type | Use it for |
| --------- | ---------- |
| `Article` | News articles, features, and opinion pieces |
| `Video` | Video stories with embedded players |
| `Web Story` | Visual stories for mobile readers |
| `Gallery` | Photo galleries. You can reorder the items from the dashboard. |
| `LiveBlog` | Live coverage of events, with updates |

- **Live coverage:** Create a `LiveBlog` post, then add updates in the dashboard. Updates support pinned entries, author attribution, and rich HTML. Your site gets them from the [live blog updates endpoint](/dxp/api-reference/content-delivery/live-blog-updates).
- **News feeds and section pages:** Get posts by category, tag, or author from the [post listing endpoint](/dxp/api-reference/content-delivery/post-listing). Filter operators such as `__eq`, `__in`, and `__gte` are in [Core concepts](/dxp/documentation/getting-started/core-concepts).
- **Fast pages at high volume:** Content Delivery API responses include cache tags. Use them to clear only the changed pages from your CDN cache. See [Cache tags](/dxp/documentation/getting-started/core-concepts#cache-tags-cds).
- **SEO and social sharing:** Posts include `short_description`, `seo_keyphrase`, and `seo_score`. Categories, tags, and authors include Open Graph and Twitter Card metadata. Use [Content scoring](/dxp/documentation/concepts-features/content-scoring) to check posts against your rules, and [Google Discover Headline](/dxp/documentation/concepts-features/google-discover-headline) to set a separate headline for Discover.
- **Multilingual publishing:** Manage and deliver content in Hindi, Tamil, Bengali, and more from one workspace.

### Control publishing in regulated industries

Banking, financial services, insurance, pharma, and healthcare teams must review content before it goes live and keep a record of each change. This table shows the Publive DXP feature for each requirement:

| Requirement | In the dashboard | Through the CMS API |
| ----------- | ---------------- | ------------------- |
| Review and approve before publishing | [Content Workflows](/dxp/documentation/content-workflows/overview): an entry moves through stages, and you cannot publish it until it reaches the stage that you set. | The status-based [Maker-Checker flow](/dxp/documentation/guides/workflows/maker-checker), with the `Approval Pending` status. |
| Control who can change which content | [Content Access Policies](/dxp/documentation/concepts-features/content-access-policies): allow or deny actions for each role and content type. | Not available. |
| Secure sign-in | [Multi-factor authentication](/dxp/documentation/getting-started/mfa) for every member. | Not applicable. |
| Record who did what | [Audit logs](/dxp/documentation/concepts-features/audit-logs) and the workflow [audit trail](/dxp/documentation/content-workflows/notifications-and-audit-trail). | Post fields `member`, `updated_by`, `approver`, `created_at`, `updated_at`, and `published_at`. |
| Release content at a set time | Schedule the post. | Set `status` to `Scheduled` and give a `scheduled_at` time. See the [CMS quickstart](/dxp/documentation/quickstarts/cms). |

Use categories to keep content for each compliance area apart, for example **Regulatory updates**, **Investor relations**, **Drug safety**, or **Clinical trials**.

<Note>
  Content Workflows and Audit logs are available on the **Custom Enterprise** plan. The workflow stage gate applies only to publishing from the dashboard. The CMS API can change the status of an entry, but it cannot change its stage.
</Note>

### Engage your readers

- **Forms:** Collect sign-ups, enquiries, and other reader data. See [Forms](/dxp/documentation/concepts-features/forms).
- **Newsletters:** Let readers subscribe from your site with the [Newsletter APIs](/dxp/api-reference/content-management/newsletter/README).
- **Reader accounts:** Let readers register and sign in on your site with the [Reader APIs](/dxp/api-reference/content-management/reader/README).

## Use AI with these docs

Every page has a contextual menu with one-click options to open it in ChatGPT, Claude, or Perplexity. For deeper AI-assisted development, connect your coding tool directly to these docs via MCP.

<Tabs>
  <Tab title="Claude Code">
    Run this command in your terminal:

    ```bash
    claude mcp add --transport http publive-docs https://docs.thepublive.com/mcp
    ```

    **Or paste this prompt into Claude Code:**

    ```
    Run this command to add the Publive docs MCP server:
    claude mcp add --transport http publive-docs https://docs.thepublive.com/mcp

    Once added, use the publive-docs MCP to give me a summary of the available Publive APIs.
    ```
  </Tab>
  <Tab title="Cursor">
    Add to your `mcp.json` (Command Palette → "Open MCP settings"):

    ```json
    {
      "mcpServers": {
        "publive-docs": {
          "url": "https://docs.thepublive.com/mcp"
        }
      }
    }
    ```

    **Or paste this prompt into Cursor:**

    ```
    Add the following to my mcp.json file to connect the Publive docs MCP server:

    {
      "mcpServers": {
        "publive-docs": {
          "url": "https://docs.thepublive.com/mcp"
        }
      }
    }

    Once saved, use the publive-docs MCP to give me a summary of the available Publive APIs.
    ```
  </Tab>
  <Tab title="VS Code">
    Create or edit `.vscode/mcp.json`:

    ```json
    {
      "servers": {
        "publive-docs": {
          "type": "http",
          "url": "https://docs.thepublive.com/mcp"
        }
      }
    }
    ```
  </Tab>
  <Tab title="Windsurf">
    Open **Windsurf Settings → MCP** and add a new server, or edit `~/.codeium/windsurf/mcp_config.json`:

    ```json
    {
      "mcpServers": {
        "publive-docs": {
          "serverUrl": "https://docs.thepublive.com/mcp"
        }
      }
    }
    ```
  </Tab>
  <Tab title="Claude (Web)">
    Go to **Settings → Connectors → Add custom connector** and enter:

    - **Name:** Publive Docs
    - **URL:** `https://docs.thepublive.com/mcp`
  </Tab>
  <Tab title="Zed">
    Open **Zed Settings** (`cmd+,`) and add under `context_servers`:

    ```json
    {
      "context_servers": {
        "publive-docs": {
          "url": "https://docs.thepublive.com/mcp"
        }
      }
    }
    ```
  </Tab>
</Tabs>

Once connected, your AI tool can search endpoints, read full pages, and navigate the API reference without you having to paste anything manually.
